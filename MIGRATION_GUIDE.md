# Migration Guide: OnrampKit v0.3.11

This guide helps you migrate from the previous version of OnrampKit to v0.3.11, which introduces two major architectural changes:

1. **Server-side URL generation** - URLs are now fetched from an API instead of being constructed client-side
2. **Optional NFC module** - NFC functionality is now a separate, optional component

---

## Breaking Changes

### 1. New Method Signature (Dictionary-Based Parameters)

The `startOnrampSDK` method now accepts a dictionary of parameters instead of individual named parameters.

#### Before (v0.3.10 and earlier):

```swift
Onramp.startOnrampSDK(
    self,
    self,
    appId: 1,
    walletAddress: "0x1234...",
    flowType: 1,
    coinCode: "ETH",
    network: "ethereum",
    fiatAmount: 100.0
)
```

#### After (v0.3.11):

```swift
Onramp.startOnrampSDK(
    self,
    self,
    params: [
        "appId": 1,
        "walletAddress": "0x1234...",
        "flowType": 1,
        "coinCode": "ETH",
        "network": "ethereum",
        "fiatAmount": 100.0
    ]
)
```

**Note:** The old method signature is still available for backward compatibility but is deprecated and will be removed in a future version.

### 2. NFC Module Separation

NFC functionality is now an **optional, separate module** to reduce SDK size for apps that don't need NFC.

#### If Your App Uses NFC:

1. **Add the OnrampNfc dependency** to your `Podfile`:

```ruby
# Core SDK (required)
pod 'OnrampKit', '~> 0.3.11'

# NFC support (optional - add only if needed)
pod 'OnrampNfc', '~> 0.3.11'
```

2. **Initialize NFC** in your `AppDelegate.swift`:

```swift
import OnrampKit
import OnrampNfc

func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
    // Enable NFC support
    OnrampNfc.initialize()
    return true
}
```

3. **Run `pod install`** to update dependencies

#### If Your App Doesn't Use NFC:

- No changes needed! Simply don't include the `OnrampNfc` pod
- Your SDK bundle size will be reduced by removing NFC dependencies
- NFC-related functionality will be gracefully disabled

## What's New

### Server-Side URL Generation

- URLs are now generated by calling the Onramp API: `https://api.onramp.money/sdk-apis/generate-url`
- Client height is automatically calculated and sent to the server
- Origin ID (6 for iOS) is automatically added
- Better security and flexibility for URL construction

### Custom API Base URL (Optional)

If you need to use a custom API endpoint (for testing or different environments):

```swift
// Set custom API base URL before calling startOnrampSDK
Onramp.setApiBaseUrl("https://your-custom-api.com/sdk-apis")
```

### UI/UX Improvements

- White background during WebView loading
- Improved status bar styling (dark icons on light background)
- Better safe area handling for notched devices
- Console logging for easier debugging

## Objective-C Support

The new dictionary-based API is fully compatible with Objective-C:

**Before:**
```objc
[Onramp startOnrampSDKWithViewController:self
                                  target:self
                                   appId:1
                           walletAddress:@"0x1234..."
                                flowType:1
                                coinCode:@"ETH"
                                 network:@"ethereum"
                              fiatAmount:100.0];
```

**After:**
```objc
NSDictionary *params = @{
    @"appId": @1,
    @"walletAddress": @"0x1234...",
    @"flowType": @1,
    @"coinCode": @"ETH",
    @"network": @"ethereum",
    @"fiatAmount": @100.0
};
[Onramp startOnrampSDKWithViewController:self target:self params:params];
```

## Available Parameters

All previous parameters are still supported in the dictionary format:

| Parameter | Type | Description |
|-----------|------|-------------|
| `appId` | Int | Your application ID (required) |
| `walletAddress` | String | User's wallet address |
| `flowType` | Int | 1=Buy, 2=Sell, 3=Checkout, 4=Swap |
| `coinCode` | String | Cryptocurrency code (e.g., "ETH", "SOL") |
| `network` | String | Blockchain network (e.g., "ethereum", "spl") |
| `coinAmount` | Double | Amount of cryptocurrency |
| `fiatAmount` | Double | Amount of fiat currency |
| `merchantRecognitionId` | String | Merchant recognition ID |
| `paymentMethod` | Int | Payment method ID |
| `authToken` | String | Authentication token |
| `assetDescription` | String | NFT/Asset description (checkout flow) |
| `assetImage` | String | NFT/Asset image URL (checkout flow) |
| `fiatType` | Int | Fiat currency type |
| `phoneNumber` | String | User's phone number |
| `lang` | String | Language code (e.g., "en", "es") |
| `addressTag` | String | Address tag/memo |
| `sellCoinCode` | String | Sell coin code (swap flow) |
| `receiveCoinCode` | String | Receive coin code (swap flow) |
| `sellAmount` | Double | Sell amount (swap flow) |
| `receiveAmount` | Double | Receive amount (swap flow) |
| `sellNetwork` | String | Sell network (swap flow) |
| `receiveNetwork` | String | Receive network (swap flow) |
| `redirectUrl` | String | Redirect URL after completion |
| `defaultCoinCode` | String | Default coin to display |
| `defaultSellCoinCode` | String | Default sell coin (swap flow) |
| `isRestricted` | Bool | Enable restrictions |

## Testing Your Migration

1. Update your Podfile
2. Run `pod install`
3. Update your code to use dictionary-based parameters
4. If using NFC, initialize `OnrampNfc` in AppDelegate
5. Test all flows (Buy, Sell, Checkout, Swap)
6. Verify NFC functionality (if applicable)

## Rollback Instructions

If you need to rollback to the previous version:

```ruby
# In your Podfile
pod 'OnrampKit', '~> 0.3.10'
```

Then run `pod install` and revert your code changes.
